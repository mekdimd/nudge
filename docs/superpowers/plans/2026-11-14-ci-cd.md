# CI and release implementation plan

Goal: Add checks and version-tagged GitHub release packages in a separate PR.

Architecture: Reuse the CI workflow as the release quality gate. Install the
built wheel and source distribution outside the checkout before publishing.

Tools: GitHub Actions, uv, pytest, Python standard library.

Spec: `docs/superpowers/specs/2026-11-14-ci-cd-design.md`.

## Constraints

Python 3.12 and 3.13 on macOS Apple Silicon and Windows x64. No API keys, live desktop actions,
release publication, or changes to the launch-video branch.

## Review focus

- Installed rehearsal must work without the source checkout.
- The working directory's `.env` must work after installation.
- A mismatched version tag must fail before publication.
- A release from a branch outside `main` must fail before publication.
- Both built archives must exclude local secrets and launch-video media.

## Tasks

1. Reproduce package and configuration failures, then move fixtures into the
   package and fix installed configuration lookup. Run focused tests.
2. Add the offline installed-package check, macOS/Windows test matrix, archive
   checks, version validation, and GitHub release publication. Pin Actions.
3. Add release instructions and Actions updates. Validate workflow syntax,
   run the suite, build and install both artifacts, and test rejected tags.
4. Update the repository description, commit and push the isolated branch,
   and open and link the PR. Report local results and hosted check status.
